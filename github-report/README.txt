GITHUB OPEN-ISSUES REPORT
=========================

Назначение
Сценарий получает открытые задачи публичного репозитория cli/cli через GitHub
REST API, сохраняет исходные JSON-ответы и создаёт текстовый аналитический отчёт.

Что анализируется
- Имя и полное имя репозитория, число открытых задач и число звёзд.
- До 30 записей API. GitHub включает pull request в этот endpoint, поэтому они
  исключаются из перечня задач и статистики меток.
- Названия задач и частота меток. Дополнительно подсчитываются названия,
  содержащие слово bug без учёта регистра.

Файлы проекта
- data/repository.json — исходная информация о репозитории.
- data/issues.json — исходный ответ API со списком записей.
- output/issue-titles.txt — по одному названию настоящей задачи в строке.
- output/label-statistics.txt — частоты меток.
- output/report.txt — человекочитаемый итоговый отчёт.
- archive/report.tar.gz — архив с итоговым отчётом.
- logs/run.log — журнал этапов и ошибок.
- github-report.sh — полный автоматизированный процесс.

Требования
Нужны Bash, curl, jq, tar, grep, sort, uniq, wc и tr. Для стандартной работы
нужен доступ к api.github.com. Авторизация для публичного репозитория не нужна.

Запуск из этого каталога
  ./github-report.sh

Можно указать другой публичный репозиторий и совместимый API endpoint:
  REPORT_REPOSITORY=owner/repo ./github-report.sh
  GITHUB_API_BASE_URL=https://api.github.com ./github-report.sh

Каждый запуск заменяет JSON, списки, отчёт и архив новыми результатами.
Предыдущая версия отчёта не затирается частично: новые данные сначала скачиваются
и проверяются во временном каталоге. Ошибки фиксируются в logs/run.log.
